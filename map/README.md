# Транспортная карта — Автобусный парк г. Барановичи

Интерактивная карта маршрутов городского транспорта: тёмный премиальный интерфейс,
glassmorphism-панели, неоновые линии маршрутов, живые маркеры транспорта, карточки
остановок и транспорта, изменения движения, избранное, подписки и обращения.

**Демо:** страница `map/index.html` (статическая сборка, работает на GitHub Pages).

> ⚠️ **Демо-данные.** Реальный GPS-провайдер не подключён: маршруты, остановки,
> интервалы и позиции транспорта — демонстрационные и помечены в интерфейсе
> бейджем «Демо-данные». Они не являются реальным расписанием Автобусного парка.

## Запуск локально

Страница использует ES-модули, поэтому нужен любой статический сервер:

```bash
cd map
python3 -m http.server 8080
# откройте http://localhost:8080
```

## Возможности

- просмотр маршрутов с цветными «светящимися» линиями и остановками;
- выбор маршрута (подсветка выбранного, приглушение остальных, fit-to-route);
- карточка остановки: маршруты через остановку, ближайшие прибытия (демо-оценка);
- карточка транспорта: борт, скорость, следующая остановка, актуальность данных;
- анимированное движение автобусов (экстраполяция вдоль линии маршрута);
- поиск маршрутов, остановок и районов (`Ctrl`/`⌘` + `K`, debounce);
- фильтры маршрутов (на маршруте / задержки / изменения / избранные);
- изменения движения: задержки, временные изменения, ремонты;
- избранное и подписки на маршруты (сохраняются в `localStorage`);
- обращения «Сообщить об ошибке» (демо: сохраняются локально);
- переключатель стиля карты: Схема / Тёмная / Светлая / Гибрид;
- легенда, зум, геолокация, линейка масштаба, горячие клавиши;
- статусы данных: актуальные / устаревшие / недоступны / демо;
- индикатор качества соединения (Network Information API);
- упрощённый режим для слабых устройств (без blur/glow, редкие кадры);
- поддержка `prefers-reduced-motion`;
- мобильная версия: bottom sheet со свайпом, bottom navigation, safe-area,
  крупные touch-цели, поддержка Telegram Mini App viewport;
- fallback при отсутствии WebGL или недоступности CDN.

## Архитектура

```
map/
├── index.html               — разметка всех панелей и карточек
├── css/map.css              — стили (glassmorphism, motion, адаптив)
└── js/
    ├── main.js              — точка входа: lazy-load MapLibre, анимация, деградация
    ├── config.js            — центр города, стили карты, интервалы, TTL
    ├── demo-data.js         — Transport Domain Layer: маршруты/остановки/изменения (демо)
    ├── geo.js               — haversine, интерполяция вдоль линии, bbox
    ├── providers.js         — Data Provider Layer: интерфейс GpsProvider,
    │                          MockGpsProvider, ProviderManager (кэш, TTL, деградация)
    ├── map-controller.js    — Map Rendering Layer: MapLibre, GeoJSON-слои, выбор
    ├── state.js             — состояние + localStorage (избранное/подписки/обращения)
    └── ui.js                — Map UI Layer: панели, карточки, поиск, модальные окна
```

### Слои системы

1. **Map UI Layer** (`ui.js`, `index.html`, `map.css`) — панели, карточки, поиск,
   фильтры, статусы. Не знает, откуда приходят данные.
2. **Map Rendering Layer** (`map-controller.js`) — MapLibre GL, слои GeoJSON
   (`routes`, `stops`, `vehicles`), подсветка выбора, canvas-спрайты транспорта.
3. **Data Provider Layer** (`providers.js`) — контракт провайдера GPS:

   ```ts
   interface GpsProvider {
     name: string
     fetchVehiclePositions(): Promise<RawVehiclePosition[]>
     normalizePosition(raw: RawVehiclePosition): NormalizedVehiclePosition
     validatePosition(position: NormalizedVehiclePosition): ValidationResult
   }
   ```

   Сейчас зарегистрирован только `MockGpsProvider` (детерминированная симуляция
   движения по линии маршрута), поэтому статус данных — «Демо-данные». Реальный
   провайдер (REST/WebSocket городского GPS) подключается в `main.js` одной
   строкой без изменения UI.
4. **Transport Domain Layer** (`demo-data.js`, `geo.js`) — маршруты, остановки,
   изменения движения, геометрические вычисления (прибытия, следующая остановка).
5. **Performance/Cache Layer** — в `ProviderManager`: кэш последних валидных
   позиций, TTL (30 с), счётчик ошибок, автоматический переход в режим редких
   обновлений (graceful degradation), журнал провайдера, `health()`-статус.
6. **Admin Management Layer** — в статической сборке отсутствует; контракты
   (управление маршрутами, изменениями, модерация обращений) описаны ниже.

### Производительность

- MapLibre подгружается лениво (dynamic script/css) только на странице карты;
- GeoJSON маршрутов и остановок строится один раз и не пересоздаётся;
- на каждый кадр обновляется **только** источник `vehicles`;
- частота кадров транспорта ограничена (~15 fps, в упрощённом режиме — 1 fps);
- обработчики `move`/`zoom` троттлятся, поиск — с debounce 200 мс;
- иконки транспорта — заранее отрисованные canvas-спрайты по цвету маршрута;
- анимации — только `transform`/`opacity`;
- в фоновой вкладке live-обновления приостанавливаются;
- слабые устройства (`deviceMemory`/`hardwareConcurrency`) автоматически
  получают упрощённый режим;
- при отсутствии WebGL показывается fallback со списками маршрутов.

### Поведение при деградации

| Ситуация | Поведение |
|---|---|
| Провайдер не отвечает | кэш позиций сохраняется, статус «устаревшие», затем «недоступны» |
| 3+ ошибки подряд | автоматический переход на редкие обновления (15 с) |
| Слабая сеть (2G) | редкие обновления, пользователь видит статус |
| Нет WebGL / CDN | fallback-экран, списки маршрутов и остановок доступны |
| Нет GPS-данных | маршруты и остановки остаются доступными |

## Серверная часть (план подключения)

Статическая сборка не содержит бэкенда. Контракты для него уже заложены:

- `GET /api/map/routes`, `GET /api/map/stops` — статические данные (кэш + ETag,
  pagination, индексы по номеру маршрута и названию остановки);
- `GET /api/map/vehicles` — live-позиции (Redis/memory-кэш, TTL 30 с,
  rate limiting, reduced payload — только изменившиеся борта);
- `GET /api/map/health` — статус провайдера (аналог `ProviderManager.health()`);
- `POST /api/appeals` — обращения; `POST /api/subscriptions` — подписки
  (доставка уведомлений через Telegram-бота);
- batch-запись истории GPS, журналы провайдеров, скрытие internal-ошибок
  от пользователей.

## Ограничения и честность данных

- mock-данные никогда не выдаются за реальные: статус «Демо-данные» виден
  в шапке, карточках прибытий и транспорте;
- тайлы сторонних провайдеров (CARTO, OSM, Esri) используются только как
  подложка с обязательной атрибуцией; стиль «Схема» полностью автономен;
- дизайн интерфейса собственный, чужие логотипы и изображения не используются.
