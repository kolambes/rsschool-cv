# Карта в экосистеме Telegram: бот + Mini App + админ-панель

> **v2.** Экран карты переработан: полноэкранный тёмный модуль с
> glass-панелями, режимы «Схема / Спутник / Гибрид», встроенная векторная
> подложка улиц города, демо-геометрия по магистральным коридорам
> (а не хаотичными лучами), лента маршрутов, карточки маршрута/остановки/
> транспорта, плавная анимация автобусов, провайдеры Яндекс-геокодера и
> OSRM road-snap. Детали — в разделах ниже.

## Конфигурация через переменные окружения

Полный список — в `.env.example` (раздел «КАРТА»). Ключевое:

| Переменная | Назначение |
|---|---|
| `MAP_PROVIDER` | движок карты (`maplibre`) |
| `MAP_TILE_URL` / `MAP_STYLE_URL` / `MAP_SCHEME_STYLE_URL` | своя подложка «Схемы»: растровые тайлы или style-URL MapLibre (хосты автоматически попадают в CSP) |
| `MAP_SATELLITE_TILE_URL` / `MAP_HYBRID_STYLE_URL` | переопределение «Спутника»/«Гибрида» |
| `MAP_DEFAULT_LAT/LNG/ZOOM` | центр и зум по умолчанию |
| `GPS_ALLOWED_BOUNDS` | границы валидных GPS-позиций (`minLat,minLng,maxLat,maxLng`) |
| `YANDEX_MAPS_API_KEY` / `YANDEX_GEOCODER_API_KEY` | геокодинг остановок |
| `YANDEX_ROUTING_API_KEY` | привязка линий к дорогам через Яндекс Роутинг |
| `YANDEX_GPS_API_ENDPOINT/KEY`, `TRANSPORT_API_ENDPOINT/KEY` | живые позиции транспорта (приоритет у API автопарка) |
| `ENABLE_MAP_FEATURES` | `false` — карта выключена целиком: экран скрыт, API отвечает 503, бот сообщает о недоступности |
| `ENABLE_DEMO_MAP_DATA` | `false` — демо-геоданные скрыты и сид заблокирован |
| `ENABLE_MOCK_GPS` | пусто — тумблер в админке; `true/false` — жёстко, тумблер блокируется |
| `GPS_POLLING_INTERVAL_SECONDS` | частота опроса GPS (и клиентом, и кэшем сервера) |
| `GPS_STALE_AFTER_SECONDS` | позиции старше — не показываются (статус `stale`) |
| `GPS_MAX_SPEED_KMH` | позиции с аномальной скоростью отбрасываются |
| `REDIS_URL` | общий кэш для нескольких инстансов (redis-lite, без npm-зависимостей); при недоступности — прозрачный fallback на память |
| `MAP_CACHE_TTL_SECONDS`, `LIVE_VEHICLE_CACHE_TTL_SECONDS` | TTL кэшей статических геоданных и live-позиций |

Формат живого GPS-API: JSON-массив (или `{vehicles:[...]}`) с полями
`id/board`, `route|routeId`, `lat/lng` (`latitude/longitude`), `speed|speedKmh`,
`bearing|course|heading`, `timestamp` (сек/мс/ISO). Ключ передаётся в
`Authorization: Bearer`, `X-Api-Key` и `?apikey`. Позиции проходят валидацию
(границы, скорость, свежесть) — битые и устаревшие отбрасываются.

## Режимы карты и подложки

| Режим | Источник | Особенности |
|---|---|---|
| Схема | Встроенная векторная подложка (`map-geo-network.js` → `/api/map/config`) | работает всегда, без внешних сервисов; улицы, шоссе, ж/д, районы |
| Спутник | Esri World Imagery (растровые тайлы, атрибуция обязательна) | внешний источник; при недоступности — автоматический откат на «Схему» |
| Гибрид | Esri Imagery + подписи CARTO | как «Спутник», плюс слой подписей |

`MAP_EXTERNAL_TILES=false` полностью отключает внешние тайлы (остаётся «Схема»).
Тайлы и подписи загружаются напрямую с серверов провайдеров c их атрибуцией;
iframe и скриншоты карт не используются.

## Почему карта больше не «клубок»

1. Демо-геометрия строится по уличной сети: городское кольцо №17 — по улицам
   центра, пригородные маршруты — по общему магистральному коридору своего
   направления (Брестское, Слонимское, Северное, Минское, Ляховичское, Южное)
   с индивидуальным «съездом» только у конечной. Линии идут «по дорогам»
   схемы, а не прямыми между остановками.
2. В обзорном режиме рисуется по одному маршруту-представителю каждого
   коридора + все городские: 6–8 читаемых линий вместо 115 наложенных.
   Полный список — в ленте внизу и в поиске; выбор маршрута включает
   фокус-режим (линия, остановки и транспорт только этого маршрута).
3. Остановки показываются ярусами: крупные узлы — раньше, остальные — при
   приближении; в фокус-режиме — только остановки выбранного маршрута.

## Провайдеры реальных геоданных (Яндекс / OSRM)

Контракт `MapDataProvider` в `map-module.js`:

```js
provider = {
  name, available(),
  geocode(query),            // адрес/остановка → координаты
  getRouteGeometry(points),  // привязка последовательности точек к дорогам
}
```

- **Яндекс Геокодер** (`YANDEX_GEOCODER_API_KEY`): админ-кнопка
  «Геокодировать остановки (Яндекс)» подставляет реальные координаты
  остановок по названию (порциями по 10, dry-run поддерживается API).
  Используется только серверный HTTP-геокодер по ключу в рамках условий
  Яндекс API; тайлы Яндекса в стороннем движке и iframe не используются.
- **OSRM** (`OSRM_URL`): кнопка «Привязать к дорогам» в редакторе геометрии
  строит линию направления по дорожной сети через координаты его остановок
  (предпросмотр → «Сохранить»). Для продакшена — self-hosted OSRM; для
  тестов допустим демо-сервер проекта OSRM (лёгкая нагрузка).
- **GPS автобусов**: публичного API Яндекса с позициями автобусов
  Барановичей не существует — позиции не выдумываются. Работает контракт
  `GpsProvider` + демо-провайдер (бейдж «Транспорт: демо»); реальный
  GPS автопарка подключается через `registerGpsProvider()`.

- **OpenStreetMap (бесплатно, без ключей)**: `npm run import:osm-stops`
  (`--dry-run` для отчёта, `--from-file файл.json` для офлайн-импорта) —
  скрипт берёт из Overpass API остановки Барановичей и населённые пункты
  района, сопоставляет по названию с расписанием и заполняет `map_stop_geo`
  с `source='osm'`. Ручные (`admin`) координаты не перезаписываются.
  Данные OSM — лицензия ODbL, атрибуция уже присутствует на карте.

Путь к реальным данным: `npm run import:osm-stops` (или Яндекс-геокодер из
админки) → «Привязать к дорогам» (OSRM) для линий → удалить демо-геоданные.
Всё — без остановки сервиса; демо-записи замещаются и помечены `source`.

Этот документ описывает модуль карты, добавленный в проект: как он устроен,
как связан с ботом, расписанием, избранным, подписками и обращениями,
и как перевести его с демо-геоданных на реальные.

## Без отдельного входа

Пользователь уже находится в Telegram, поэтому в Mini App нет формы входа:

- Mini App отправляет `x-telegram-init-data` с каждым запросом;
- сервер валидирует подпись `initData` (HMAC, TTL) — `verifyTelegramInitData` в `server.js`;
- Telegram ID из проверенного `initData` связывает пользователя с подписками
  (`map_route_subscriptions`), избранным (`user_favorites_sync`), обращениями
  и напоминаниями;
- избранное продолжает мгновенно работать через `localStorage`, а на сервере
  хранится снапшот по Telegram ID — при смене устройства список восстанавливается;
- админ-панель — отдельный вход по `ADMIN_KEY`/ролям, как и раньше.

## Deep-links: бот → нужный экран карты

Бот открывает конкретные экраны Mini App через hash и `start_param`:

| Цель | Ссылка |
|---|---|
| Экран карты | `WEBAPP_URL/#map` |
| Карта с выбранным маршрутом | `WEBAPP_URL/#map_route_<route_id>` |
| Карта с выбранной остановкой | `WEBAPP_URL/#map_stop_<ключ остановки>` |
| Через t.me | `https://t.me/<bot>?start=map` или `start=map_route_<id>` |

Обработка: `initialView()` в `app.js` сохраняет цель в `window.__mapDeepTarget`
и открывает view `map`; `map-screen.js` применяет цель после загрузки данных.
Уведомление об изменении движения содержит кнопку «Открыть на карте» с
соответствующим deep-link.

## API карты

Публичные (кэш 60 с, общий rate limit публичного чтения):

- `GET /api/map/data` — маршруты с геометрией направлений + остановки с
  координатами (компактный формат, GeoJSON собирает клиент);
- `GET /api/map/vehicles?routes=id1,id2` — позиции транспорта (фильтр по
  маршрутам, без фильтра — не более 120 бортов);
- `GET /api/map/alerts` — активные изменения движения;
- `GET /api/map/health` — покрытие геоданными и статус GPS-провайдера.

Пользовательские (нужен валидный `initData`):

- `GET/POST /api/map/subscriptions` — подписки на изменения маршрутов;
- `GET/POST /api/user/favorites` — синхронизация избранного.

Админские (право `schedule`, т.е. роль `admin`):

- `GET /api/admin/map/overview|stops|routes|route-geometry`
- `POST /api/admin/map/stops` — координаты остановки `{key, lat, lng}` / `{key, remove:true}`
- `POST /api/admin/map/route-geometry` — линия направления `{routeId, directionCode, geometry:[[lng,lat],…]}`
- `POST /api/admin/map/alerts` — публикация/архив/удаление изменения (публикация рассылает уведомления подписчикам)
- `POST /api/admin/map/settings` — `{demoVehicles: true|false}`
- `POST /api/admin/map/demo-seed` — `{}` заполнить демо-геоданные / `{clear:true}` удалить

## Слой GPS-провайдеров

Контракт в `map-module.js`:

```js
provider = {
  name: "my-gps",
  isDemo: false,
  async fetchVehiclePositions() { /* сырые данные из городской GPS-системы */ },
  normalizePosition(raw) { /* → {id, routeId, lat, lng, bearing, speedKmh, timestamp} */ },
  validatePosition(position) { /* → {ok, errors} */ }
};
mapModule.registerGpsProvider(provider);
```

Пока реальный GPS не подключён, работает `demo`-провайдер (включается в
админке или `MAP_DEMO_VEHICLES=true`): борта детерминированно движутся по
сохранённой геометрии направлений. Пользователь всегда видит честный статус:
бейдж «Транспорт: демо-данные» или ничего, если провайдер выключен.
Ответ провайдера кэшируется на 2 с; при ошибке провайдера сервер не падает,
а отдаёт пустой список со статусом `error`.

## Геоданные: от демо к реальным

В расписании (XML) координат нет, поэтому геослой ведётся отдельно:

1. **Демо-режим** (для проверки интерфейса): `npm run seed:map-demo` или
   кнопка «Заполнить демо-геоданные» в админке. Маршруты раскладываются
   схематично лучами от центра города; все записи `source='demo'`;
   пользователи видят бейдж «Схема (демо-геоданные)».
2. **Реальные данные** (постепенно, без остановки сервиса):
   - вкладка «Карта» → выбрать остановку → клик по карте задаёт координаты
     (`source='admin'`, демо-точка замещается);
   - «Построить по остановкам» строит черновик линии направления по
     координатам его остановок; линию можно уточнить кликами по карте или
     правкой JSON и сохранить;
   - когда демо больше не нужно — «Удалить демо-геоданные» (админ-записи
     остаются).

Ключ остановки — нормализованное название (`normalized_name` из расписания),
поэтому координаты одной физической остановки автоматически распространяются
на все маршруты через неё и переживают повторный импорт XML.

## Изменения движения и подписки

- Админ публикует изменение (задержка/объезд/ремонт/перекрытие/информация)
  во вкладке «Карта».
- Изменение сразу видно: чипы над картой, пометка «⚠» в списке маршрутов,
  блок в карточке маршрута.
- Всем подписчикам маршрута бот отправляет сообщение с кнопкой
  «Открыть на карте» (повторная публикация не дублирует рассылку —
  поле `notified_at`).
- Подписка — кнопка «Подписаться на изменения» в карточке маршрута на карте
  (работает только в Telegram, к Telegram ID).

## Производительность

- MapLibre GL (vendored, `public/vendor/`, лицензия BSD-3) загружается лениво —
  только при первом открытии экрана карты; сам экран — часть обычного app shell;
- статические геоданные кэшируются на сервере (60 с) и отдаются одним
  компактным ответом; транспорт — отдельным лёгким запросом раз в 8 с и только
  когда экран карты открыт и вкладка видима;
- при выбранном маршруте клиент запрашивает борта только этого маршрута
  (`?routes=`), без фильтра сервер ограничивает ответ 120 бортами;
- превью в расписании — обычный `<canvas>` 2D без MapLibre;
- CSP дополнен `worker-src 'self' blob:` — MapLibre рендерит в web worker.
