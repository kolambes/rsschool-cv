# Карта в экосистеме Telegram: бот + Mini App + админ-панель

Этот документ описывает модуль карты, добавленный в проект: как он устроен,
как связан с ботом, расписанием, избранным, подписками и обращениями,
и как перевести его с демо-геоданных на реальные.

## Что появилось

| Часть системы | Что добавлено |
|---|---|
| Mini App | Экран «Карта» в нижней навигации; блок «На карте» в расписании с превью маршрута |
| Telegram-бот | Команда `/map`, кнопка «Карта» в клавиатуре, web_app-кнопки, deep-links |
| Сервер | `map-module.js`: геоданные, GeoJSON API, слой GPS-провайдеров, изменения движения |
| Админ-панель | Вкладка «Карта»: координаты остановок, линии маршрутов, изменения, демо-режим |
| БД (SQLite) | Таблицы `map_stop_geo`, `map_route_geometry`, `map_alerts`, `map_route_subscriptions`, `user_favorites_sync`, `map_settings` |

## Без отдельного входа

Пользователь уже находится в Telegram, поэтому в Mini App нет формы входа:

- Mini App отправляет `x-telegram-init-data` с каждым запросом;
- сервер валидирует подпись `initData` (HMAC, TTL) — `verifyTelegramInitData` в `server.js`;
- Telegram ID из проверенного `initData` связывает пользователя с подписками
  (`map_route_subscriptions`), избранным (`user_favorites_sync`), обращениями
  и напоминаниями;
- избранное продолжает мгновенно работать через `localStorage`, а на сервере
  хранится снапшот по Telegram ID — при смене устройства список восстанавливается;
- админ-панель — отдельный вход по `ADMIN_KEY`/ролям, как и раньше.

## Deep-links: бот → нужный экран карты

Бот открывает конкретные экраны Mini App через hash и `start_param`:

| Цель | Ссылка |
|---|---|
| Экран карты | `WEBAPP_URL/#map` |
| Карта с выбранным маршрутом | `WEBAPP_URL/#map_route_<route_id>` |
| Карта с выбранной остановкой | `WEBAPP_URL/#map_stop_<ключ остановки>` |
| Через t.me | `https://t.me/<bot>?start=map` или `start=map_route_<id>` |

Обработка: `initialView()` в `app.js` сохраняет цель в `window.__mapDeepTarget`
и открывает view `map`; `map-screen.js` применяет цель после загрузки данных.
Уведомление об изменении движения содержит кнопку «Открыть на карте» с
соответствующим deep-link.

## API карты

Публичные (кэш 60 с, общий rate limit публичного чтения):

- `GET /api/map/data` — маршруты с геометрией направлений + остановки с
  координатами (компактный формат, GeoJSON собирает клиент);
- `GET /api/map/vehicles?routes=id1,id2` — позиции транспорта (фильтр по
  маршрутам, без фильтра — не более 120 бортов);
- `GET /api/map/alerts` — активные изменения движения;
- `GET /api/map/health` — покрытие геоданными и статус GPS-провайдера.

Пользовательские (нужен валидный `initData`):

- `GET/POST /api/map/subscriptions` — подписки на изменения маршрутов;
- `GET/POST /api/user/favorites` — синхронизация избранного.

Админские (право `schedule`, т.е. роль `admin`):

- `GET /api/admin/map/overview|stops|routes|route-geometry`
- `POST /api/admin/map/stops` — координаты остановки `{key, lat, lng}` / `{key, remove:true}`
- `POST /api/admin/map/route-geometry` — линия направления `{routeId, directionCode, geometry:[[lng,lat],…]}`
- `POST /api/admin/map/alerts` — публикация/архив/удаление изменения (публикация рассылает уведомления подписчикам)
- `POST /api/admin/map/settings` — `{demoVehicles: true|false}`
- `POST /api/admin/map/demo-seed` — `{}` заполнить демо-геоданные / `{clear:true}` удалить

## Слой GPS-провайдеров

Контракт в `map-module.js`:

```js
provider = {
  name: "my-gps",
  isDemo: false,
  async fetchVehiclePositions() { /* сырые данные из городской GPS-системы */ },
  normalizePosition(raw) { /* → {id, routeId, lat, lng, bearing, speedKmh, timestamp} */ },
  validatePosition(position) { /* → {ok, errors} */ }
};
mapModule.registerGpsProvider(provider);
```

Пока реальный GPS не подключён, работает `demo`-провайдер (включается в
админке или `MAP_DEMO_VEHICLES=true`): борта детерминированно движутся по
сохранённой геометрии направлений. Пользователь всегда видит честный статус:
бейдж «Транспорт: демо-данные» или ничего, если провайдер выключен.
Ответ провайдера кэшируется на 2 с; при ошибке провайдера сервер не падает,
а отдаёт пустой список со статусом `error`.

## Геоданные: от демо к реальным

В расписании (XML) координат нет, поэтому геослой ведётся отдельно:

1. **Демо-режим** (для проверки интерфейса): `npm run seed:map-demo` или
   кнопка «Заполнить демо-геоданные» в админке. Маршруты раскладываются
   схематично лучами от центра города; все записи `source='demo'`;
   пользователи видят бейдж «Схема (демо-геоданные)».
2. **Реальные данные** (постепенно, без остановки сервиса):
   - вкладка «Карта» → выбрать остановку → клик по карте задаёт координаты
     (`source='admin'`, демо-точка замещается);
   - «Построить по остановкам» строит черновик линии направления по
     координатам его остановок; линию можно уточнить кликами по карте или
     правкой JSON и сохранить;
   - когда демо больше не нужно — «Удалить демо-геоданные» (админ-записи
     остаются).

Ключ остановки — нормализованное название (`normalized_name` из расписания),
поэтому координаты одной физической остановки автоматически распространяются
на все маршруты через неё и переживают повторный импорт XML.

## Изменения движения и подписки

- Админ публикует изменение (задержка/объезд/ремонт/перекрытие/информация)
  во вкладке «Карта».
- Изменение сразу видно: чипы над картой, пометка «⚠» в списке маршрутов,
  блок в карточке маршрута.
- Всем подписчикам маршрута бот отправляет сообщение с кнопкой
  «Открыть на карте» (повторная публикация не дублирует рассылку —
  поле `notified_at`).
- Подписка — кнопка «Подписаться на изменения» в карточке маршрута на карте
  (работает только в Telegram, к Telegram ID).

## Производительность

- MapLibre GL (vendored, `public/vendor/`, лицензия BSD-3) загружается лениво —
  только при первом открытии экрана карты; сам экран — часть обычного app shell;
- статические геоданные кэшируются на сервере (60 с) и отдаются одним
  компактным ответом; транспорт — отдельным лёгким запросом раз в 8 с и только
  когда экран карты открыт и вкладка видима;
- при выбранном маршруте клиент запрашивает борта только этого маршрута
  (`?routes=`), без фильтра сервер ограничивает ответ 120 бортами;
- превью в расписании — обычный `<canvas>` 2D без MapLibre;
- CSP дополнен `worker-src 'self' blob:` — MapLibre рендерит в web worker.

## Файлы модуля

```
bar-bus/
├── map-module.js              # сервер: БД, API, провайдеры, уведомления
├── scripts/seed-demo-geo.js   # npm run seed:map-demo [-- --clear]
└── public/
    ├── map-screen.js/.css     # экран «Карта» + блок в расписании
    ├── admin-map.js           # вкладка «Карта» админки (+стили в admin.css)
    └── vendor/maplibre-gl.*   # MapLibre GL JS 4.7.1 (BSD-3-Clause)
```

Правки существующих файлов: `server.js` (require + init + диспетчеризация
API + команда `/map`, кнопка, deep-link, CSP), `public/app.js` (view `map`
в навигации/хэшах, мост `window.BarBusApp`, синхронизация избранного),
`public/index.html`, `public/admin.html`, `public/admin.js` (вкладка, мост
`window.BarBusAdmin`), `.env.example` (`MAP_DEMO_VEHICLES`).
