# Передаточная документация продукта

**Продукт:** Telegram-бот, Telegram Mini App и админ-панель для автобусного
парка г. Барановичи (расписания, маршруты, обращения граждан, новости,
реклама, услуги, контакты руководства, разнарядка водителей).

**Версия:** 0.1.0 · **Тип поставки:** исходный код + документация · **Лицензия:** передаётся заказчику вместе с исходниками.

Этот документ описывает, **что передаётся**, **что умеет продукт** и **как им
пользоваться**. Технические инструкции по установке на удалённый сервер —
в отдельном документе [VPS_DEPLOY_RU.md](VPS_DEPLOY_RU.md).

---

## 1. Что передаётся

| Компонент | Описание |
|---|---|
| Исходный код | `server.js`, `db.js`, `route-importer.js`, `duty-roster.js`, `content-filter.js`, `public/`, `scripts/` |
| Интерфейс | Mini App пассажира, админ-панель (`public/`), самостоятельно размещённые шрифты, иконки, изображения |
| База данных | SQLite (`node:sqlite`) — создаётся автоматически при первом запуске |
| Документация | Это руководство, инструкция по развёртыванию, пример конфигурации `.env.example` |
| Скрипты | Импорт расписаний, проверки, тесты, локальные вспомогательные команды |

**Зависимостей нет** — проект работает на «чистом» Node.js 24+ без сторонних
npm-пакетов. Это упрощает установку, аудит и сопровождение.

**Не входит в передачу** (и не должно): настоящий `.env` с токенами, рабочая
база с персональными данными, приватные вложения обращений, логи. Секреты
генерируются уже на сервере.

## 2. Возможности

### 2.1 Mini App пассажира (открывается из Telegram или в браузере)

- **Расписание** по маршруту, направлению и остановке; сегменты «Сегодня /
  Будни / Выходные».
- **«Живой» рейс** — расчётное положение автобуса по времени рейса (не GPS),
  с выделением текущей остановки и пройденного пути на схеме маршрута.
- **Ближайшие рейсы** — поиск «откуда → куда» с прямыми рейсами и **маршрутами
  с пересадкой** (показывает время обоих автобусов и остановку пересадки).
- **Сетка маршрутов** по типам: городские, пригородные, междугородние
  (каждый тип — свой мнемонический цвет).
- **Поиск остановки**, схема маршрута со всеми остановками и временами.
- **Избранное** и **напоминания** (будильник за N минут до рейса).
- **Обращения** — жалоба, вопрос, реклама, СТО: текст, фото, аудио.
- **Услуги, новости, реклама, контакты руководства, карта парка.**
- **Работает офлайн** (PWA): шрифты, интерфейс и оболочка кэшируются.

### 2.2 Telegram-бот

- Приём обращений граждан (`/appeal`, текст/фото/аудио в чате).
- Вход администратора через чат (`/admin`).
- Рассылка разнарядки водителям и служебные уведомления.
- Работает через **long polling** — отдельный webhook настраивать не нужно.

### 2.3 Админ-панель (`/admin`)

Разделы: **расписание**, **обращения**, **разнарядка**, **услуги**,
**уведомления**, **посещаемость/статистика**, **администраторы**, **о нас**,
**реклама**, **новости**.

Возможности: загрузка XML-расписаний (с аудитом и резервными копиями/откатом),
ответы на обращения и смена статусов, управление рекламой/новостями/услугами,
загрузка CSV-разнарядки, управление ролями сотрудников.

## 3. Роли и доступы

Вход в админку — по секретному ключу `ADMIN_KEY` (заголовок) **или** по
проверенной Telegram-личности из списка `ADMIN_IDS`.

| Роль | Доступ |
|---|---|
| `admin` | Полный доступ ко всем разделам |
| `appeals_manager` | Обращения, жалобы, вопросы, предложения |
| `ads_manager` | Рекламные заявки и реклама |
| `dispatcher` | Расписание и разнарядка |
| `moderator` | Обращения |
| `sto_manager` | Обращения по СТО и услугам |
| `driver` | Водительский доступ к своей разнарядке |

Администраторы из `ADMIN_IDS` автоматически заводятся в базе с ролью `admin`
при первом запуске.

## 4. Ежедневная эксплуатация

- **Загрузить расписание** — админка → раздел расписания → загрузка XML
  (или CLI `npm run import:routes -- /path city|suburban|intercity`).
  Импорт затрагивает только таблицы расписания; обращения, новости, реклама и
  сотрудники не удаляются.
- **Ответить на обращение** — уведомление о новом обращении → открыть в
  админке → ответить → сменить статус → закрыть чат, когда вопрос решён.
- **Контент** — новости, реклама, услуги, контакты руководства
  редактируются в админке; публичные изображения — в `public/uploads`.
- **Разнарядка** — загрузить CSV; при привязке Telegram ID + табельного
  номера водитель получает свои назначения в боте. Ежедневная отправка —
  `DUTY_ROSTER_DAILY_ENABLED` / `DUTY_ROSTER_DAILY_SEND_TIME` (по умолчанию 18:00).

Подробные пошаговые сценарии — в разделах 15–18 инструкции по развёртыванию.

## 5. Технические характеристики

- **Среда:** Node.js **24+** (обязательно — используется встроенный
  `node:sqlite`, которого нет в старых версиях).
- **Зависимости:** отсутствуют (0 npm-пакетов).
- **Хранилище:** SQLite-файл `data/app.db` (создаётся сам).
- **Транспорт бота:** long polling (webhook не нужен). Один активный процесс
  на один `BOT_TOKEN`.
- **Интерфейс:** статические HTML/CSS/JS + PWA/Service Worker; шрифты
  размещены локально (внешних CDN нет — работает офлайн и не зависит от
  сторонних сервисов).
- **Требуется для production:** VPS (Ubuntu/Debian), домен с HTTPS, Nginx как
  обратный прокси на `127.0.0.1:3000`, Telegram-бот от `@BotFather`.
- **Проверка работоспособности:** `GET /api/health`.

## 6. Безопасность

Проведён полный аудит безопасности (сервер, данные, клиент, бот). Ключевые
факты:

- Проверка Telegram initData по HMAC, timing-safe сравнения ключей и подписей.
- Параметризованный SQL, защита от path traversal, whitelist загрузок с
  проверкой magic-байтов, приватные вложения вне веб-корня с подписанными
  ссылками с истечением.
- Бот на long polling — нет входящего webhook, апдейты нельзя подделать.
- Критично для прод-настройки (задаётся в `.env`, см. `.env.example`):
  `NODE_ENV=production`, `REQUIRE_TELEGRAM_AUTH=true`, `TRUST_PROXY=true` +
  `TRUSTED_PROXY_IPS`, сильный `ADMIN_KEY` (16+ символов), фиксированный
  `FILE_ACCESS_SECRET`. При неверной настройке приложение выводит громкие
  `[security]`-предупреждения в логах старта.
- `YANDEX_MAPS_API_KEY` (если используется) отдаётся клиенту по дизайну —
  **ограничьте его по домену** в консоли Яндекса.

**Держать в секрете:** `.env`, `BOT_TOKEN`, `ADMIN_KEY`, `FILE_ACCESS_SECRET`,
рабочую базу и приватные вложения. При смене подрядчика — ротировать секреты.

## 7. Резервное копирование и обновление

**Бэкап** (минимум): `.env`, `data/app.db`, `data/uploads`,
`public/uploads`. Хранить копию вне сервера. Процедура — раздел 19 инструкции.

**Обновление:** остановить сервис → сохранить текущую папку → распаковать
новый архив → перенести `.env`, базу и `uploads` → заменить папку → запустить.
Пошагово — раздел 20 инструкции.

---

## 8. Что требуется от заказчика для запуска

1. **VPS** с Ubuntu 22.04/24.04 (или похожим Debian-Linux) и SSH-доступом.
2. **Домен или поддомен** (например `bus.example.com`) с A-записью на IP VPS.
3. **Telegram-бот** от `@BotFather` (токен) и Telegram ID администраторов.
4. **XML-файлы расписаний** (городские / пригородные / междугородние).
5. При необходимости — **ключ Яндекс.Карт**, ограниченный по домену.

## 10. Приёмка — короткий чеклист

- Приложение запущено (`systemctl status bar-bus` → `active (running)`).
- `GET /api/health` отвечает без ошибки локально и по HTTPS.
- Mini App и `/admin` открываются по HTTPS.
- Бот отвечает на `/start`, кнопка меню Telegram ведёт на домен.
- Администратор входит в `/admin`, расписание отображается.
- Тестовое обращение создаётся и приходит в админку; ответ доходит до пассажира.
- Бэкап-процедура проверена хотя бы один раз.
- Секреты в `.env` заданы на сервере; `[security]`-предупреждений в логах нет.

Полная версия чеклиста — разделы 21 и 25 инструкции по развёртыванию.
