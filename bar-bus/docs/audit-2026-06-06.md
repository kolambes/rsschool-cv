## Область проверки

Проверены основные части проекта:

- публичное Telegram Mini App;
- админ-панель;
- серверные API;
- импорт XML-расписаний;
- обращения и вложения;
- новости, избранное, услуги;
- роли сотрудников;
- базовая нагрузка и smoke-сценарии.

Проверка выполнялась с разделением по направлениям: безопасность, интерфейс, расписание/XML и админские сценарии.

## Исправлено

### Безопасность

- Убран слабый `ADMIN_KEY` по умолчанию.
- Добавлена защита от слабого админ-ключа.
- Подмена роли через `x-admin-role` больше не работает без явного `ALLOW_ADMIN_ROLE_OVERRIDE=true`.
- Очистка обращений, уведомлений и журнала расписания ограничена только полным администратором.
- Вложения в чат обращений больше не сохраняются до проверки доступа клиента.
- Токен клиентского чата больше не передаётся через URL.
- Добавлены лимиты на лайки/просмотры новостей и XML-импорт.
- Обработка некорректного JSON теперь возвращает контролируемую ошибку.
- Некорректный URL статического файла больше не должен валить сервер.

### Расписание и XML

- После импорта XML, ручного редактирования и отката очищается публичный кэш расписания.
- Полная замена XML требует выбранный тип расписания: город, пригород или межгород.
- Полная замена больше не удаляет расписания других типов транспорта.
- CLI-импорт теперь рекурсивно читает XML и требует тип расписания.
- Валидация времени XML не пропускает часы вне `00..23` и минуты вне `00..59`.
- Маска дней `0000000` отклоняется, чтобы не получить невидимое расписание.
- Зависшие отложенные XML-замены автоматически возвращаются в очередь.
- Служебный маршрут 17 больше не добавляется при импорте пригорода или межгорода.

### Интерфейс и UX

- Тема приложения больше не перетирает тёмный режим Telegram при первом запуске.
- Новости не помечаются все просмотренными сразу при открытии вкладки.
- Избранное сохраняет раскрытый будильник после обновления данных.
- Значок количества избранного не обрезается нижним меню.
- Восстановление скролла работает и для вкладки избранного.
- Подсветка ближайшего рейса использует полный ключ рейса, а не только время.
- При ошибке загрузки расписания исчезает бесконечный skeleton.

### Админ-панель

- Удаление времени в расписании больше не удаляет весь рейс случайно.
- Скрыты опасные кнопки очистки для ролей ниже администратора.
- Уведомления больше не создаются как "черновик без отправки".
- Убрана лишняя роль "Обращения" из формы сотрудников.
- Добавлена проверка Telegram ID сотрудника.
- Добавлен безопасный `.env.example`.

## Осталось сделать вручную

Если Telegram `BOT_TOKEN` уже был показан, отправлен или попал в чужие руки, его нужно перевыпустить через BotFather. Кодом это безопасно сделать нельзя.

Рекомендация перед боевым запуском:

- перевыпустить `BOT_TOKEN`;
- задать новый `ADMIN_KEY`;
- задать отдельный `FILE_ACCESS_SECRET`;
- не хранить `.env` в git;
- на сервере держать секреты только в переменных окружения или закрытом `.env`.
